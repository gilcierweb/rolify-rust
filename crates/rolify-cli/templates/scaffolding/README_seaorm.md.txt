# SeaORM Migrations for Rolify

Generated by `rolify-cli generate --backend seaorm {role_name} {holder_name}`.

## Overview

This directory contains a SeaORM migration file for the rolify role management
system. The migration uses the raw-SQL approach: it carries one statement
array per dialect (Postgres, MySQL, SQLite), each byte-derived from the
canonical per-engine SQL, and selects the right array at runtime through a
match on the database backend, so the schema is identical to the Diesel and
SQLx migrations for every supported engine.

## Files

- `seaorm/0000000001_rolify_create_tables.rs` - SeaORM migration implementing `MigrationTrait`

## Running Migrations with SeaORM

### Using SeaORM CLI

```bash
# Generate a new migration (not needed for rolify - fresh generate only)
sea-orm-cli migrate generate -n "description"

# Run migrations
sea-orm-cli migrate up

# Revert
sea-orm-cli migrate down
```

### Using SeaORM Migrator in Code

```rust
use sea_orm_migration::prelude::*;
use sea_orm::{Database, DatabaseConnection};

async fn run_migrations(db: &DatabaseConnection) -> Result<(), DbErr> {
    // The generated migration is registered in the Migrator
    Migrator::up(db, None).await
}
```

## Migration Structure

The generated migration file (`0000000001_rolify_create_tables.rs`) contains
six const statement arrays (an up and a down array per dialect) and a runtime
backend match in both `up()` and `down()` (statements below are truncated;
the real file carries the full canonical SQL per engine):

```rust
use sea_orm::{DbBackend, DbErr};
use sea_orm_migration::prelude::*;

#[derive(DeriveMigrationName)]
pub struct Migration;

// One array per dialect, each byte-derived from the canonical per-engine
// up.sql: Postgres uses GENERATED ALWAYS AS IDENTITY, MySQL uses
// AUTO_INCREMENT with utf8mb4, SQLite uses the INTEGER PRIMARY KEY rowid
// alias.
const POSTGRES_UP_STATEMENTS: &[&str] = &[r"...", /* 4 statements */];
const MYSQL_UP_STATEMENTS: &[&str] = &[r"...", /* 4 statements */];
const SQLITE_UP_STATEMENTS: &[&str] = &[r"...", /* 4 statements */];

// Every down array drops the join table first (FK child), then roles.
const POSTGRES_DOWN_STATEMENTS: &[&str] =
    &["DROP TABLE IF EXISTS users_roles;", "DROP TABLE IF EXISTS roles;"];
const MYSQL_DOWN_STATEMENTS: &[&str] =
    &["DROP TABLE IF EXISTS users_roles;", "DROP TABLE IF EXISTS roles;"];
const SQLITE_DOWN_STATEMENTS: &[&str] =
    &["DROP TABLE IF EXISTS users_roles;", "DROP TABLE IF EXISTS roles;"];

#[async_trait::async_trait]
impl MigrationTrait for Migration {
    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        let (backend, statements) = match manager.get_database_backend() {
            backend @ DbBackend::Postgres => (backend, POSTGRES_UP_STATEMENTS),
            backend @ DbBackend::MySql => (backend, MYSQL_UP_STATEMENTS),
            backend @ DbBackend::Sqlite => (backend, SQLITE_UP_STATEMENTS),
            other => {
                return Err(DbErr::Custom(format!(
                    "rolify migrations support Postgres, MySQL, and SQLite; got {other:?}"
                )));
            }
        };
        // Statements execute ONE AT A TIME: the Postgres extended protocol
        // rejects multiple commands inside a single prepared statement.
        for statement in statements {
            let stmt = sea_orm::Statement::from_string(backend, (*statement).to_owned());
            manager.get_connection().execute_raw(stmt).await?;
        }
        Ok(())
    }

    async fn down(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        // The same runtime match over the three down arrays: join table
        // first, then roles, on every dialect.
        let (backend, statements) = match manager.get_database_backend() {
            backend @ DbBackend::Postgres => (backend, POSTGRES_DOWN_STATEMENTS),
            backend @ DbBackend::MySql => (backend, MYSQL_DOWN_STATEMENTS),
            backend @ DbBackend::Sqlite => (backend, SQLITE_DOWN_STATEMENTS),
            other => {
                return Err(DbErr::Custom(format!(
                    "rolify migrations support Postgres, MySQL, and SQLite; got {other:?}"
                )));
            }
        };
        for statement in statements {
            let stmt = sea_orm::Statement::from_string(backend, (*statement).to_owned());
            manager.get_connection().execute_raw(stmt).await?;
        }
        Ok(())
    }
}
```

## Registering with Migrator

Add the migration to your `Migrator` struct. The emitted file name
(`0000000001_rolify_create_tables.rs`) starts with a digit, so it cannot be
declared as a plain module (a Rust identifier cannot start with a digit);
alias it with a `#[path]` attribute module instead:

```rust
use sea_orm_migration::prelude::*;
use sea_orm_migration::sea_orm::DatabaseBackend;

// Points at the emitted migration file (adjust the relative path to where
// you copied it inside your migration project).
#[path = "0000000001_rolify_create_tables.rs"]
mod rolify_create_tables;

// In your migrator file (e.g., src/migrator.rs)
pub struct Migrator;

#[async_trait::async_trait]
impl MigratorTrait for Migrator {
    fn migrations() -> Vec<Box<dyn MigrationTrait>> {
        vec![
            Box::new(rolify_create_tables::Migration),
            // ... other migrations
        ]
    }
}
```

## Schema Details

The correct dialect is selected at runtime for Postgres, MySQL, and SQLite:
`up()` and `down()` match on `SchemaManager::get_database_backend()` and
execute the statement array of the connected engine, one statement per
prepared statement. `Statement::from_string` only tags a statement with a
dialect, it never translates DDL, so every dialect ships its own canonical
statement set.

### Tables Created

- **roles**: Stores role definitions with sentinel `''` strategy for global/class scopes
- **users_roles**: Join table with FK cascade to roles

### Indexes and Constraints

- `roles_triple_unique`: UNIQUE (name, resource_type, resource_id)
- `idx_roles_resource`: INDEX (resource_type, resource_id)
- `idx_roles_name`: INDEX (name)
- `users_roles_pair_unique`: UNIQUE (user_id, role_id)
- FK: users_roles.role_id -> roles.id ON DELETE CASCADE

## Using with rolify-seaorm Adapter

```rust
use rolify_core::config::RolifyConfig;
use rolify_seaorm::SeaOrmStore;
use sea_orm::DatabaseConnection;

let config = RolifyConfig::builder().build()?;
let store = SeaOrmStore::new(db, config);

// Same API as other adapters
store.add_role(&user_id, &RoleName::from("admin")).await?;
```

## Custom Table Names

If you used custom `--roles-table` or `--join-table` flags, the generated
migration will have the custom names substituted into every dialect array.
Update your entity models accordingly.
