# SeaORM Migrations for Rolify

Generated by `rolify-cli generate --backend seaorm {role_name} {holder_name}`.

## Overview

This directory contains a SeaORM migration file for the rolify role management
system. The migration uses the raw-SQL approach (executing the canonical SQL
via `Statement::from_string`) to ensure byte-identical schema to the Diesel
and SQLx migrations.

## Files

- `seaorm/0000000001_rolify_create_tables.rs` - SeaORM migration implementing `MigrationTrait`

## Running Migrations with SeaORM

### Using SeaORM CLI

```bash
# Generate a new migration (not needed for rolify - fresh generate only)
sea-orm-cli migrate generate -n "description"

# Run migrations
sea-orm-cli migrate up

# Revert
sea-orm-cli migrate down
```

### Using SeaORM Migrator in Code

```rust
use sea_orm_migration::prelude::*;
use sea_orm::{Database, DatabaseConnection};

async fn run_migrations(db: &DatabaseConnection) -> Result<(), DbErr> {
    // The generated migration is registered in the Migrator
    Migrator::up(db, None).await
}
```

## Migration Structure

The generated migration file (`0000000001_rolify_create_tables.rs`) contains:

```rust
use sea_orm_migration::prelude::*;

#[derive(DeriveMigrationName)]
pub struct Migration;

#[async_trait::async_trait]
impl MigrationTrait for Migration {
    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        // Executes the canonical up.sql for the detected database backend
        let sql = r#"..."#; // Canonical up.sql for the engine
        let stmt = Statement::from_string(manager.get_database_backend(), sql);
        manager.get_connection().execute(stmt).await.map(|_| ())
    }

    async fn down(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        // Drops join table first, then roles (FK order)
        for statement in ["DROP TABLE IF EXISTS users_roles;", "DROP TABLE IF EXISTS roles;"] {
            let stmt = Statement::from_string(manager.get_database_backend(), statement);
            manager.get_connection().execute(stmt).await.map(|_| ())?;
        }
        Ok(())
    }
}
```

## Registering with Migrator

Add the migration to your `Migrator` struct:

```rust
use sea_orm_migration::prelude::*;
use sea_orm_migration::sea_orm::DatabaseBackend;

// In your migrator file (e.g., src/migrator.rs)
pub struct Migrator;

#[async_trait::async_trait]
impl MigratorTrait for Migrator {
    fn migrations() -> Vec<Box<dyn MigrationTrait>> {
        vec![
            Box::new(m20240101_000001_rolify_create_tables::Migration),
            // ... other migrations
        ]
    }
}
```

## Schema Details

The migration executes the canonical SQL for the detected database backend
at runtime via `SchemaManager::get_database_backend()`. This ensures the
correct dialect (Postgres/MySQL/SQLite) is used.

### Tables Created

- **roles**: Stores role definitions with sentinel `''` strategy for global/class scopes
- **users_roles**: Join table with FK cascade to roles

### Indexes and Constraints

- `roles_triple_unique`: UNIQUE (name, resource_type, resource_id)
- `idx_roles_resource`: INDEX (resource_type, resource_id)
- `idx_roles_name`: INDEX (name)
- `users_roles_pair_unique`: UNIQUE (user_id, role_id)
- FK: users_roles.role_id -> roles.id ON DELETE CASCADE

## Using with rolify-seaorm Adapter

```rust
use rolify_core::config::RolifyConfig;
use rolify_seaorm::SeaOrmStore;
use sea_orm::DatabaseConnection;

let config = RolifyConfig::builder().build()?;
let store = SeaOrmStore::new(db, config);

// Same API as other adapters
store.add_role(&user_id, &RoleName::from("admin")).await?;
```

## Custom Table Names

If you used custom `--roles-table` or `--join-table` flags, the generated
migration will have the custom names substituted. Update your entity models
accordingly.
