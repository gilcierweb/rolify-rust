# Diesel Migrations for Rolify

Generated by `rolify-cli generate --backend diesel {role_name} {holder_name}`.

## Overview

This directory contains Diesel migrations for the rolify role management system.
The migrations create the `roles` and `users_roles` tables with the proper
indexes and foreign key constraints to support global, class-scoped, and
instance-scoped roles.

## Files

- `migrations/postgres/0000000001_rolify_create_tables/up.sql` - Postgres up migration
- `migrations/postgres/0000000001_rolify_create_tables/down.sql` - Postgres down migration
- `migrations/mysql/0000000001_rolify_create_tables/up.sql` - MySQL up migration
- `migrations/mysql/0000000001_rolify_create_tables/down.sql` - MySQL down migration
- `migrations/sqlite/0000000001_rolify_create_tables/up.sql` - SQLite up migration
- `migrations/sqlite/0000000001_rolify_create_tables/down.sql` - SQLite down migration

## Running Migrations

### Using Diesel CLI

```bash
# Run all pending migrations
diesel migration run

# Revert the last migration
diesel migration revert

# Redo the last migration (revert + run)
diesel migration redo
```

### Using Diesel Migrations in Code

```rust
use diesel_migrations::{embed_migrations, EmbeddedMigrations, MigrationHarness};
use diesel::pg::PgConnection;

// Embed the migrations at compile time
pub const MIGRATIONS: EmbeddedMigrations = embed_migrations!("migrations/postgres");

fn run_migrations(conn: &mut PgConnection) {
    conn.run_pending_migrations(MIGRATIONS).expect("migrations failed");
}
```

## Schema Details

### Roles Table

```sql
CREATE TABLE roles (
    id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name          VARCHAR(255) NOT NULL,
    resource_type VARCHAR(191) NOT NULL DEFAULT '',
    resource_id   VARCHAR(191) NOT NULL DEFAULT '',
    created_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT roles_triple_unique UNIQUE (name, resource_type, resource_id)
);
CREATE INDEX idx_roles_resource ON roles (resource_type, resource_id);
CREATE INDEX idx_roles_name ON roles (name);
```

### Join Table (users_roles)

```sql
CREATE TABLE users_roles (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    CONSTRAINT users_roles_pair_unique UNIQUE (user_id, role_id)
);
```

The join column type follows `--holder-id-type` (default integer, shown
here for Postgres: `BIGINT`; the `uuid` kind emits `UUID`, the `string`
kind emits `VARCHAR(191)`).

Match it to your holder table's actual primary key type:

- `users.id` is `BIGINT`, `BIGSERIAL`, or `BIGINT GENERATED ... AS IDENTITY`
  (Rails 5.1+ default, matches the gem's `t.references`): keep the default.
- `users.id` is `SERIAL` or `INTEGER` (4 bytes, 1 to 2147483647): edit the
  emitted `user_id` column from `BIGINT` to plain `INTEGER`. Never write
  `SERIAL` on the join column: `SERIAL`/`BIGSERIAL` are PK-definition
  pseudo-types that create a sequence; a join column carries the plain type.
- `users.id` is `UUID`: regenerate with `--holder-id-type uuid`.
- String holder ids: regenerate with `--holder-id-type string`.

When `--with-holder-fk` is on, the two sides must be the exact same type:
Postgres rejects a foreign key between `BIGINT` and `INTEGER`
(incompatible types), and MySQL likewise requires identical column types.

## Using with rolify-diesel Adapter

```rust
use diesel::Connection;
use diesel::pg::PgConnection;
use rolify_core::config::RolifyConfig;
use rolify_core::query::{ResourceFilter, RoleQuery};
use rolify_core::resource::ResourceRef;
use rolify_core::role::{ResourceId, RoleName};
use rolify_core::store::RoleStore;
use rolify_core::user::RolifyUser;
use rolify_diesel::DieselStore;

let config = RolifyConfig::builder().build()?;
let mut store = DieselStore::new(&config);
let mut conn = PgConnection::establish("postgres://user:pass@localhost/db")?;

// Grant the global admin role: the store SPI mirrors the gem's adapter
// calls (find_or_create_by dedupes the role row, add links the holder).
// Holder ids parse under the configured holder-id kind (default integer,
// so the canonical id here is "1").
let admin = store.find_or_create_by(&mut conn, &RoleName::from("admin"), ResourceRef::Global)?;
store.add(&mut conn, &ResourceId::from("1"), &admin)?;

// Check membership through the where_ ladder.
let roles = store.where_(&mut conn, &ResourceId::from("1"), &RoleQuery {
    name: &RoleName::from("admin"),
    filter: ResourceFilter::Global,
})?;
assert_eq!(roles.len(), 1);

// Prefer the idiomatic path in application code: implement
// rolify_core::user::RolifyUser on your holder type, then call
// user.add_role(&RoleName::from("admin"), ResourceRef::Global) and
// user.has_role(&RoleName::from("admin"), ResourceFilter::Global).
// Scoped grants pass the scope as an argument:
// ResourceRef::Class("Forum") or
// ResourceRef::Instance("Post", &ResourceId::from("42")).
```

## Custom Table Names

If you used custom `--roles-table` or `--join-table` flags, update the
`RolifyConfig` accordingly:

```rust
let config = RolifyConfig::builder()
    .role_table("custom_roles")
    .join_table("custom_users_roles")
    .build()?;
```

## Engine-Specific Notes

### PostgreSQL
- Uses `BIGINT GENERATED ALWAYS AS IDENTITY` for auto-incrementing IDs
  (the modern equivalent of `BIGSERIAL`, 8 bytes)
- The default `users_roles.user_id BIGINT` assumes a bigint holder PK. If
  your holder PK is `SERIAL`/`INTEGER` (4 bytes), change the join column to
  plain `INTEGER`; if it is `UUID`, regenerate with `--holder-id-type uuid`
- Uses `VARCHAR(255)` and `VARCHAR(191)` for string columns
- Timestamps use `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`

### MySQL
- Uses `BIGINT AUTO_INCREMENT` for auto-incrementing IDs
- Uses `utf8mb4` character set with `utf8mb4_bin` collation for byte-exact comparison
- Uses `ENGINE=InnoDB` for foreign key support

### SQLite
- Uses `INTEGER PRIMARY KEY` (rowid alias) for IDs
- Uses `TEXT` for string columns
- Timestamps stored as `TEXT` with `CURRENT_TIMESTAMP` default
- Requires `PRAGMA foreign_keys = ON` for FK enforcement
