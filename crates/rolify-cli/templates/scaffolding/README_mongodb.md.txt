# MongoDB Documents for Rolify

Generated by `rolify-cli generate --backend mongodb {role_name} {holder_name}`.

## Overview

This directory contains the MongoDB role document struct and index notes for
the rolify role management system. The CLI generates a Rust struct definition
matching the expected document shape in MongoDB, plus index setup notes.

**Important**: The CLI only documents the schema. The actual index creation
and document management is handled by the `rolify-mongodb` adapter at runtime
(per Phase 5 D-10 / D-17 convergence).

## Files

- `mongo/role.rs` - Role document struct (`RoleDoc`) + consumer-side `ConsumerRoleIds`
- `mongo/INDEX_NOTES.md` - Index setup documentation

## Document Shape

### RoleDoc

```rust
pub struct RoleDoc {
    pub id: ObjectId,           // MongoDB _id
    pub name: String,           // Role name (byte-exact)
    pub resource_type: Option<String>,  // Explicit null for global/class
    pub resource_id: Option<String>,    // Explicit null for global/class
    pub user_ids: Vec<ObjectId>,        // User references (two-sided HABTM)
}
```

### ConsumerRoleIds

```rust
pub struct ConsumerRoleIds {
    pub role_ids: Vec<ObjectId>,  // Two-sided HABTM on consumer side
}
```

## Index Notes

The `INDEX_NOTES.md` file documents the required index:

```
Unique compound index: (name: 1, resource_type: 1, resource_id: 1)
  - Ensured idempotently at store setup
  - Deduplicates identically to the SQL sentinel '' strategy
```

The `rolify-mongodb` adapter (Phase 5) will create this index idempotently
at store initialization.

## Two-Sided HABTM Semantics

When a role is added/removed, BOTH sides are updated:

- **Role document**: `$addToSet` / `$pull` on `user_ids`
- **Consumer document**: `$addToSet` / `$pull` on `role_ids`

When a role is removed, emptiness is checked AFTER removal:
- If `user_ids` becomes empty, the role document may be removed
  (per `remove_role_if_empty` config, default true).

## Using with rolify-mongodb Adapter

```rust
use rolify_core::config::RolifyConfig;
use rolify_mongodb::MongoStore;
use mongodb::Database;

let config = RolifyConfig::builder().build()?;
let store = MongoStore::new(db, config);

// Same API as other adapters
store.add_role(&user_id, &RoleName::from("admin")).await?;
```

## Custom Table Names

If you used custom `--roles-table` or `--join-table` flags, the generated
document struct comments will reflect the custom names. The actual MongoDB
collection name is determined by the adapter configuration.

## Sentinel Strategy

The CLI documents the MongoDB equivalent of the SQL sentinel `''` strategy:
- Global/class scope roles have `resource_type: None` and `resource_id: None`
  (explicit null, not absent fields)
- This matches the gem's Mongoid behavior where empty strings are used
